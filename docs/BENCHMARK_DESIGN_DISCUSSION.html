TIA Benchmark 怎么设计：一个三层框架

"策略赚不赚钱"只是三种要测的东西之一，而且是最不适合做日常开发指标的那种。本稿提出把评测拆成三层，各自用不同逻辑打分，并给出每层的具体 task 和当前进展，供会上讨论。

TIA 定位需要交易的客户，量化或主观都有；中低频，日内级别
策略类型Systematic 与 Discretionary 两类
产出形式直接生成策略代码与回测，也会调用现成因子库
当前状态第二层已有可运行基准；第一、三层待设计

01核心判断：要测的是三件不同的事

从 TIA 的定位出发，用户交给它的任务可以拆成三个问题。它们的评判逻辑完全不同，混在一起就会得出错误结论。

依赖关系是单向的。搜索建立在翻译正确之上，收益建立在搜索有效之上，反过来不成立。一个连用户描述都写错的 agent，它搜出的"好策略"没有意义；一个搜索很强的 agent，它的样本外收益仍然大半由行情决定。所以从投入产出看，优先级是 1 > 2 > 3。

02为什么第三层不能当日常指标

同事在群里的判断是对的：只有实盘是金标准；常见标的没有"严格"的样本外；样本外一旦用来验证就泄漏了；交易比赛的 hold-out 只能评一次。这里补充两点，一点是把"泄漏"说得更精确，一点是 LLM 特有的问题。

"用"一次是什么意思

泄漏不是把样本外数据放进优化器才发生，而是看到结果之后做了任何决定就发生了。看完觉得夏普低回去改参数、比较五个候选选最高的、把表现差的方向排除掉，这些都算。策略代码没有前视，但你本人就是优化器。这是选择偏差，不是前视偏差，但后果一样：选出的那个在样本外的成绩不再是无偏估计。

下面是一个模拟。两万个候选策略全部是纯噪声（真实夏普 = 0），hold-out 长度 2.4 年。每次从 N 个候选里按 hold-out 夏普挑最好的：

LLM 的泄漏比人严重

人类 trader 拿到匿名、变换过的数据还得猜。LLM 的训练集里有整段市场历史，看 BTC 2021 年那段 K 线的形状就能认出来，然后"不自觉地"偏多。比赛那套"改名、加 transform"对 LLM 不够。切断记忆只有两条路：合成数据（把已知结构埋进去，正确答案精确可知，可无限生成），或对真实数据做强变换（block bootstrap、跨标的拼接、收益重排），让形状本身不可识别。

结论。第三层只能做成每个大版本烧一次的认证关口，不能做成每天跑的开发指标。日常迭代靠第一、二层，这两层没有泄漏问题。

03第一层：翻译准确性 建议主 benchmark

结构类似 SWE-bench：每条任务是一段自然语言的策略描述加一个参考实现，打分看 TIA 的产出和参考实现的差距。目前没有人在做这件事，而它直接对应 TIA 的核心价值。

Task输入评判
Identify bad alpha含缺陷的策略描述或代码能否定位到预先标注的缺陷类别：前视偏差、摩擦成本超过收益、数据挖掘、逻辑不自洽、过拟合信号
Systematic implementation规则性描述："RSI < 30 买入，> 70 卖出"生成代码的持仓序列与参考实现的一致率；PnL 偏差；是否有前视
Discretionary interpretation判断性描述："市场恐慌时加仓"参考答案是几位 trader 各写一版；TIA 的持仓落在他们的分布内即算对
Factor library usage描述中引用已有因子调到正确的因子、参数正确、没有重复造轮子
Ambiguity detection含歧义的描述是否主动反问；反问的是不是关键歧义点，而不是无关细节
Friction accounting描述含成本、成交时点要求手续费、滑点、T+1、调仓容忍带是否按要求写对

Systematic 与 Discretionary 的差别落在哪

不需要为 discretionary 单独设计一套评判逻辑。差别只在参考答案：systematic 的参考实现唯一；discretionary 的参考实现是一组，由几位有经验的 trader 独立写出。TIA 的输出落在这组的分布内就算对，落在外面就是理解错了。Ambiguity detection 在 discretionary 场景下尤其重要，因为好的 trader 助手会先问清楚再动手。

关于 "identify bad alpha"

这个 task 跨了第一、二层。给一段描述或代码问"逻辑上有什么问题"，是第一层，有标准答案，建议以这个版本为主。给一段回测统计问"这个 alpha 是不是过拟合"，是第二层，更主观，难量化，可以后做。它特别有价值的原因是：实盘前发现策略是坏的，比发现好策略更重要，而且每个真实用户遇到的坏策略脱敏后都能变成一条数据。

指标：逻辑正确率（每题 0/1）、持仓序列相关性、缺陷定位准确率、歧义反问率、前视偏差检出率。另外看 token 成本和耗时，但不进主排序。

04第二层：搜索质量 已有可运行基准

这是仓库里已经在跑的部分。核心设计是不比裸收益，比"在给定空间里搜到第几名"。

  • 任务：6 个 ETF × 3 个滚动窗口 + 1 条零漂移合成序列，Test 段落在不同行情。
  • Oracle：每个任务事先穷举或采样全空间，拿到 Val/Test 夏普的完整分布。
  • 主指标：percentile_val，agent 选中的策略在全空间 Val 夏普里的分位。Test 只对最终策略评一次，算 regret 作副指标，不参与任何决定。
  • 基线：同预算、零 token 的随机搜索。LLM 架构要进榜，先要稳定赢过它。
  • 汇总：先对种子取均值，再对任务取均值，bootstrap 给置信区间。

读法。三个 LLM 架构互相分不出差别，而且都输给随机搜索。原因不是 LLM 不行，是空间太小太平：一万多个点里前十名夏普只差 0.1，随机抽 8 次就到 0.89 分位，推理没地方发挥。这也是一个教训：裸 Test 夏普上 LLM 是赢的（它们都挑了 momentum 120 这类教科书参数，而 2024–26 的 SPY 恰好奖励长周期动量），如果只看那个数字会得出相反的结论。

正在做的事：空间已扩到 v2（新增均值回归、突破、RSI、信号组合，加 regime 过滤和波动率缩放，153,090 个点），prompt 同步升级。v2 oracle 正在重建，重跑结果会补进来。这一轮回答的问题是：空间够大时，LLM 的推理能不能赢过随机搜索。

第二层还可以加的 task

  • Sample efficiency：best-so-far 曲线下面积，同预算到多高分位。轨迹数据已经在记。
  • Hypothesis quality：agent 每轮会写"这个参数应该更好，因为 X"。拿它的预测排名和实际排名算相关性，能直接检验推理是在起作用还是随机游走配上了听起来对的理由。目前没人做，差异化高。
  • Out-of-distribution：在训练任务之外的标的和时段上，分位掉多少。

05第三层：收益认证，不是 benchmark

两种形式，都是发版关口，每个版本用一次：

  • Blind hold-out：匿名、强变换后的真实数据，评一次封存，下次换新的。参考交易比赛的做法。
  • Synthetic with planted alpha：合成序列里埋入已知 alpha，看 TIA 找没找到、找错的比例多少。正确答案精确已知，可无限生成，也切断了 LLM 的记忆。现有的零漂移合成任务是它的最简版本（埋的 alpha 是零，所有方法都应该找不到，目前确实如此）。

06建议与待讨论的问题

优先级建议

  1. Identify bad alpha 先做：数据最容易积累，最接近核心价值，可直接量化。
  2. Systematic implementation 的持仓一致率 先做：机器可验证，不依赖人工标注。
  3. Ambiguity detection 其次：discretionary 场景的关键区分点，但需要标注歧义点。
  4. 第二层 v2 结果与 hypothesis quality 其次：基础设施已有，等数据。
  5. Blind hold-out 认证流程 发版前再做。

需要大家决定的

  1. TIA 的核心任务更接近第一层还是第二层？是"把用户的想法正确实现"，还是"代替用户探索什么策略好"？这决定主 benchmark 放哪一层。
  2. 第一层的参考实现谁来写？systematic 的可以由工程写；discretionary 的需要几位 trader 各写一版，这是人力成本最高的一环。
  3. Identify bad alpha 的缺陷分类表怎么定？需要 trader 给出一份"实盘前最常见的坑"清单作为标注体系。
  4. 真实用户 case 能否脱敏后进入 benchmark？这是第一层数据能否持续增长的前提。
  5. hold-out 的消耗节奏。一个版本一套，谁来保管、何时开封、开封后数据怎么处理。
