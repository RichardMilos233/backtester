例 1：where() 默认填 NaN，碰到回测引擎遇 NaN 不平仓，导致暴跌期死锁满仓

跨模块配合的坑 · sa_nan_lock_01
1. 题目

规则要求进入高波动期（Q1/Q2）必须立刻清仓。但信号函数用了 .where(allowed) 没传默认值（输出 NaN），而回测引擎碰到 NaN 的处理是“维持原仓位不动”，结果暴跌时多头仓位被死锁在场内：

def build_regime_filtered_signal(df):
    raw_sig = (df["close"] > df["close"].rolling(40).mean()).astype(float)
    return raw_sig.where(df["regime"].isin(["Q3", "Q4"]))  # 坑 1：没填 other=0.0，高波动期输出 NaN

def run_backtest_step(open_price, current_cash, current_position, signal):
    if pd.isna(signal): trade_shares = 0                   # 坑 2：引擎遇 NaN 不交易（维持原仓位），只有 signal==0 才平仓！
    elif signal == 0:   trade_shares = -current_position
2. 真实例子对比：做对的模型 vs 做错的模型
✅ 做对：claude-opus-5.5 / gpt-6-astra精准命中
一眼看穿两个函数拼在一起的后果：
"flaw_types": ["logical_inconsistency"],
"explanation": "Series.where(cond) defaults to other=NaN.
In Q1/Q2 the signal becomes NaN, and the engine sets
trade_shares = 0 (hold position) instead of liquidating."
❌ 做错：claude-haiku-4-5 / gpt-5.4-mini乱贴标签
看见参数名叫 open_price 就条件反射瞎猜“偷看未来”：
"flaw_types": ["logical_inconsistency", "lookahead_bias"],
"explanation": "...consumed by an open-price execution
function without a shift, creating lookahead bias."
3. 一句话诊断：小模型习惯看变量名“瞎猜贴标签”，只有旗舰模型能顺着数据流看懂两个模块拼在一起后的真实后果。

例 2：resample('3D') 默认时间戳打在第一天，导致周一偷看周三收盘价

pandas 默认参数的坑 · sa_resample_left_02
1. 题目

把日线聚合成 3 日线算均线，再对齐回日线。在 pandas 里，resample('3D') 默认是左闭合、左标签（label='left'），.last() 会把第 3 天的收盘价贴在第 1 天的时间戳上，一做 ffill() 就穿越了：

htf_close = df["close"].resample("3D").last()  # 坑：'3D' 默认 label='left'，把周三收盘价打在周一上！
htf_bull = (htf_close > htf_close.rolling(10).mean()).astype(int)
daily_htf_bull = htf_bull.reindex(df.index, method="ffill")  # 周一直接偷看到周三的收盘结果
2. 真实例子对比：做对的模型 vs 做错的模型
✅ 做对：claude-opus-5.5 / gpt-6-astra原理全对
清楚指出 '3D' 默认 label='left', closed='left'：
"flaw_types": ["lookahead_bias"],
"explanation": "For '3D', pandas defaults to closed='left'
and label='left'. Each bin [t, t+3d) is labeled t, but .last()
takes Day t+2's close, leaking it onto Day t via ffill."
❌ 做错：deepseek-v3.2 / gpt-5.4-mini默认参数记反
虽然猜了前视偏差，但把 pandas 默认参数完全记反了：
"flaw_types": ["lookahead_bias"],
"explanation": "The resample('3D') operation with default
label='right' and closed='right' creates 3-day bars..."
3. 一句话诊断：很多模型只是背下了“看到 resample 就报前视偏差”的套路，其实连 pandas 最基础的默认参数正反都没记清。

例 3：给一段完全没问题的代码，8 个模型里有 6 个硬挑刺报错

大模型的“挑刺强迫症” · sa_clean_subtle_12
1. 题目

给一段完全合规的“突破过去 40 日高点买入 + 跌破持仓最高价 7% 移动止损”代码（已经严格写了 .shift(1)，每笔交易独立记高点，平仓也重置），看模型敢不敢说“没问题”：

prior_max40 = df["close"].rolling(40, min_periods=40).max().shift(1).to_numpy() # 严格排除当日
for i in range(len(df)):
    c = close_arr[i]
    if state == 0 and not np.isnan(prior_max40[i]) and c > prior_max40[i]:
        state = 1; entry_peak = c                                               # 入场初始化高点
    elif state == 1:
        entry_peak = max(entry_peak, c)
        if c < 0.93 * entry_peak: state = 0; entry_peak = 0.0                   # 止损平仓并重置
2. 真实例子对比：做对的模型 vs 做错的模型
✅ 做对：仅 gpt-6-astra / claude-opus-5.5稳住不乱报
逐项检查后坚定给出“无缺陷”：
"has_flaw": false, "flaw_types": [],
"explanation": "No flaw found. rolling(40).max().shift(1)
is strictly causal; entry_peak ratchets per trade and
resets cleanly on exit."
❌ 做错：deepseek-v3.2 / v4-pro / sonnet-4-6 等 6 家没病硬挑刺
为了完成“找茬任务”硬编荒唐理由：
"has_flaw": true, "flaw_types": ["lookahead_bias"],
"explanation": "min_periods=40 with shift(1) means first
signal is at index 41, creating lookahead/survivorship bias!"
3. 一句话诊断：一旦让大模型扮演“代码审查员”，绝大多数模型就会染上“不挑出毛病不罢休”的强迫症，在研发中制造大量假警报。

例 1：把已经返回 0/1 的信号函数当成均线价格，再去跟 400 块的股价比较，写成永远满仓死拿

不能只看夏普打分 · sys_mom_01
1. 题目

收盘价高于 60 日均线就做多（仓位 1），否则空仓（0）。提示可直接调用内部因子库函数 compute_moving_average_signal(df, window=60)（文档已写明该函数直接返回 0/1 信号）。

2. 真实例子对比：做对的模型 vs 做错的模型
✅ 做对：gpt-6-astra / claude-sonnet-4-6一致率 100% · 夏普 0.72
看懂函数已经返回 0/1 信号，直接返回：
def build_strategy(df):
    sig = compute_moving_average_signal(df, window=60)
    return {"signals": sig, "slippage_rate": 0.0005, ...}
❌ 做错：deepseek-v3.2一致率 0.2% · 夏普 1.21（假高分！）
把 0/1 当成均线价格，再拿 400 块的股价去比大小：
def build_strategy(df):
    sma_signal = compute_moving_average_signal(df, window=60)
    signals = (df['close'] > sma_signal).astype(float) # 400 > {0,1} 永远为 True！
    return {"signals": signals, ...}
3. 一句话诊断：模型没看清函数返回值契约；更关键的是，写错的代码变成死拿不动，在牛市里回测夏普（1.21）反而比正确代码（0.72）更高——说明评测量化代码绝不能只看夏普率。

例 2：月末调仓代码前面全写对了，最后多写一行 replace(0, method='ffill')，把平仓的 0 全刷成 1

画蛇添足导致永不卖 · v3_impl_03
1. 题目

前 60 天空仓；之后只在每个月最后一个交易日收盘时评估一次信号（站上 60 日均线且 20 日涨幅 > 0 则仓位设为 1，否则设为 0），当月其余交易日保持上月末仓位不变。

2. 真实例子对比：做对的模型 vs 做错的模型
✅ 做对：gpt-6-astra / claude-opus-5.5TradeF1 = 1.00
非调仓日留 NaN，用 ffill() 同时延续 1.0 和 0.0：
month_end = ~df.index.to_period("M").duplicated(keep="last")
rebalance = month_end & (np.arange(len(df)) >= 60)
targets = ((close > sma60) & (mom20 > 0)).astype(float)
signals = targets.where(rebalance).ffill().fillna(0.0)
❌ 做错：deepseek-v3.2TradeF1 = 0.00（永远不卖）
循环里明明写对了，循环外多加一行把所有 0 刷成 1：
for i in range(len(df)):
    if not month_end_mask[i]:
        signals.iloc[i] = current_position; continue
    ...
signals = signals.replace(to_replace=0.0, method='ffill') # 把平仓 0 全刷成 1！
3. 一句话诊断：模型把“空仓状态（0.0）”和“没调仓的缺失值（NaN）”搞混了，最后画蛇添足的一行代码让策略变成只买不卖。

例 3：把 15% 目标波动率写成 15.0（放大了 100 倍），又被后面的 .clip(1.5) 截断掩盖

被截断掩盖的静默故障 · v3_impl_02
1. 题目

当满足趋势条件时做多，并按 15% 目标年化波动率除以 20 日实际年化波动率 来缩放仓位，最大杠杆不超过 1.5 倍。

2. 真实例子对比：做对的模型 vs 做错的模型
✅ 做对：claude-sonnet-4-6 / gpt-6-astra一致率 100%
分子分母统一用小数（0.15），仓位随波动率正常呼吸：
rv20 = np.sqrt(252.0 * (returns.pow(2).rolling(20).mean()))
target_vol = 0.15                              # 与分母量纲一致
scale = (target_vol / rv20).clip(upper=1.5)
❌ 做错：deepseek-v3.2一致率 28.2%（永远顶格 1.5x）
分母是 0.15，分子写 15.0，算出 100 倍杠杆被 clip(1.5) 掩盖：
zero_mean_vol = np.sqrt((df['return']**2).rolling(20).mean() * 252) # ~0.15
target_vol = 15.0                              # 放大了 100 倍！15.0 / 0.15 = 100x
vol_scaling = (target_vol / zero_mean_vol).clip(upper=1.5) # 永远卡死在 1.5
3. 一句话诊断：百分数与小数量纲混用，被 .clip(1.5) 截断后既不报错也不越界，变成实盘中最危险的“静默风控失效”。

例 4：注释里写着 # 计算 Wilder RSI，手底下却写成简单平均 .rolling(14).mean()

偷换金融公式 · v3_impl_13
1. 题目

多子策略组合中，子策略 C 要求在 14 日 Wilder RSI < 35 时触发做多，并对触发的子策略按波动率倒数归一化分配仓位。

2. 真实例子对比：做对的模型 vs 做错的模型
✅ 做对：gpt-6-astra / claude-sonnet-4-6一致率 100%
严格按 Wilder 定义使用 alpha = 1/14 的指数平滑：
avg_gain = gain.ewm(alpha=1.0/14.0, adjust=False).mean()
avg_loss = loss.ewm(alpha=1.0/14.0, adjust=False).mean()
rs = avg_gain / avg_loss
rsi = 100.0 - (100.0 / (1.0 + rs))
❌ 做错：deepseek-v3.2一致率 20.0%
注释写得头头是道，下一行直接用简单均线糊弄：
# 计算RSI (14日Wilder RSI)
avg_gain = gain.rolling(window=14, min_periods=14).mean() # 偷换成简单平均！
avg_loss = loss.rolling(window=14, min_periods=14).mean()
3. 一句话诊断：“嘴上说懂、手底下偷懒”——模型知道金融指标的名字，写代码时却顺手用最简单的 .rolling().mean() 敷衍过去。
