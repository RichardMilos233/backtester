# Agent 策略搜寻实验平台搭建计划

## 要回答的两个问题

1. 同一套搜索框架下，换 foundation model，谁在封存测试段上更稳。
2. 同一个模型下，换 agent 架构，结果会不会明显不一样。

两问分开做。同时换模型和架构，分不清是谁起的作用。

## 已经有的

- 回测底座：全复权 SPY、T+1 开盘成交、万五滑点、万五佣金、5% 调仓容忍带。
- 数据三段：Train 60% / Validation 20% / Test 20%。模型只看 Train 反馈。Validation 选优。Test 只在定稿后跑一次。
- 四种拓扑：A 手写基线，B 单研究员，C 研究员加规则审查，D 双研究员。
- 真实模型调用：`OpenAICompatibleClient`，网关可换 `LLM_MODEL`。
- 现成脚本：`scripts/run_live_benchmark_experiment.py` 只覆盖 A/B/C/D × 5 个种子 × 一个模型。

## 现在缺的

这些不做，后面的对比不可信。

1. **模型不是实验因子。** 模型名写在环境变量里，结果表里没有 model 列，换模型要手改脚本。
2. **架构只到 A/B/C/D。** Proposal 里的 SOTA 记忆、反思日志、信号相关性去重、分层调度、角色流水线、树搜索、对抗辩论都还没接到编排器上。
3. **预算不公平。** D 把迭代次数对半拆给两个研究员。C 里被打回的轮次仍占迭代名额。有的模型 JSON 解析失败会掉进默认 SMA 50，分数看起来像“找到了策略”。
4. **过程指标没落账。** 缺少：有效提案率、解析失败次数、审查打回次数、实际回测次数、耗时、是否用了 fallback。
5. **网格不能断点续跑。** 一次 502 会整表作废，也没有“同一组配置不重复烧调用”的记录。
6. **主指标要事先写死。** 现在容易看完 Test 再挑好看的表。主指标定为 Test 夏普；并列看过拟合落差（Validation 夏普 − Test 夏普）、Test 回撤、Test 换手。Validation 只用来选策略，不用来给架构排名。

不在这一期做的：多标的、放开任意 Python 策略、用 Laya/Jev 当研究员。信号空间仍是 momentum 和 MACD。Laya 以后可以当审查打分器，不和 foundation model 混在同一张表里。

## 平台长什么样

一次实验是一行配置，跑完写一行结果。

```text
ExperimentSpec
  model            网关模型名
  infra            架构代号
  seed
  max_backtests    真正送进回测的次数上限（各架构对齐）
  temperature
  memory_length
  feedback_metrics
  selection_metric  默认 sharpe_ratio
        │
        ▼
   Orchestrator.run()
        │
        ▼
   docs/experiments/runs.jsonl     每轮提案、反馈、是否回测
   docs/experiments/summary.csv    每个 (model, infra, seed) 一行
```

编排器按 `infra` 字符串分发，不再写死 A/B/C/D。A/B/C/D 保留为第一批架构。

公平规则：

- 比的是 **送进回测的次数**，不是循环轮数。被审查打回不计入回测次数。
- 解析失败记一笔 `parse_fail`，不偷偷换成 SMA 50 去参赛。该种子标为失败，汇总时单独列出。
- 温度、切分、摩擦、初始资金、反馈字段、选优指标全部锁死。
- 同一 `(model, infra, seed)` 已有成功记录则跳过。

## 第一阶段：换模型，框架不动

固定架构为 **C**（研究员 + 规则审查）。这是现在最完整、又还没引入新机制的一档。

建议第一批模型（网关上有、延迟和价格差得开）：

| 代号 | 模型 | 角色 |
| :--- | :--- | :--- |
| 快 | `deepseek-chat` | 便宜、已经跑通过 |
| 强推理 | `claude-sonnet-4-6` 或网关上可用的 Sonnet | 看更强模型会不会少走弯路 |
| 另一个家族 | `gemini-2.5-flash` 或 `qwen3-coder` | 避免结论只来自一个供应商 |

每个模型 5 个种子（42–46），每次最多 8 次回测。先用 1 个种子把 JSON 能否稳定解析跑通，再铺开。

产出：一张模型对照表。主排序是 5 个种子的 Test 夏普均值。同时报标准差、过拟合落差、换手、解析失败率。

这一阶段结束时选定 **一个后续架构实验用的模型**。默认用 deepseek-chat，除非另一家在 Test 夏普上稳定更好、而且解析失败率不高。选模型只看这一阶段的 Validation 汇总；Test 数字进报告，但不拿来回头改 prompt。

## 第二阶段：换架构，模型不动

模型冻结。一次只加一个机制，对照都是上一档，而不是六种一起上。

| 顺序 | 架构代号 | 相对上一档多出来的东西 | 主要改动 |
| :--- | :--- | :--- | :--- |
| 0 | `C` | 已有：规则审查 + FIFO 记忆 | 作为对照 |
| 1 | `C-sota` | 记忆里永远保留 Train 上夏普最高的那条 | `researcher.py` |
| 2 | `C-corr` | 新信号与已回测信号相关 ≥ 0.95 则打回 | `reviewer.py` |
| 3 | `C-reflect` | 每轮多写一段复盘，下一轮带上 | `researcher.py` |
| 4 | `C-hier` | 轮流只动一件事：均线/MACD 参数，或波动率缩放 | `orchestrator.py`，接上已有 `compute_volatility_scaled_signal` |
| 5 | `C-tree` | 同样 8 次回测预算，先分叉再沿最好的一支往下走 | `orchestrator.py` |
| 6 | `C-debate` | 一个提案、一个专门挑回撤和换手，规则审查仍在 | 新 reviewer 提示，仍走同一回测 |

角色流水线（宏观 / 研究员 / 风控三段提示）先不做。它和分层调度、辩论叠在一起，分不清是角色有用还是提示变长了。

D（双研究员）留在第一阶段的对照里即可。它把预算拆开，不适合当作后面每一档的基线。

每一档：5 种子 × 8 次回测。和 `C` 比 Test 夏普、落差、换手。没有稳定差别就停在这一档，不继续叠机制。

## 第三阶段：只做一次交叉

如果某一档架构在第二阶段明显好于 `C`，用那一档重跑另外两个模型各 5 个种子。用来看“这个架构是不是只对某一个模型有用”。不做完整的模型 × 全部架构矩阵。

## 搭建顺序

1. `ExperimentSpec` 写入 model、infra、max_backtests、seed。结果强制带上这些字段。
2. 编排器改为按 infra 分发；回测次数与解析失败按上面的规则记账；jsonl 断点续跑。
3. 一个入口脚本：`scripts/run_experiment_grid.py`，读一份小的实验清单（先写在 Python 列表里，不必上配置框架）。
4. 用 Mock 跑通网格和记账，确认失败提案不会变成假策略。
5. 第一阶段：三模型 × 架构 C × 5 种子。
6. 按上表逐档加架构，每档跑完再决定下一档做不做。

## 怎么读结果

- 主指标：Test 夏普的种子均值。
- 必须一起看：过拟合落差、Test 最大回撤、Test 换手、解析失败率。
- 5 个种子只能看方向和波动，不写成统计显著。
- Test 每个 `(model, infra, seed)` 只评估最终胜出的那一个 spec。
